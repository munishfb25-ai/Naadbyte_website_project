# NaadByte — Official Website

Premium, cinematic website for **NaadByte**, an independent music label producing
devotional, cinematic, motivational, EDM, progressive house, trance, lo-fi, rap and
instrumental music in Hindi, English and Punjabi.

Built with **React 19 + TypeScript + Vite + Tailwind CSS v4 + Framer Motion**, on
**TanStack Start / TanStack Router** (file-based routing with SSR).

---

## Quick start

Requirements: **Node.js 20+** and npm 10+ ([install via nvm](https://github.com/nvm-sh/nvm)).

```sh
git clone <repository-url>
cd naadbyte
npm install
npm run dev
```

The dev server prints a local URL (default `http://localhost:8080`).

## Content model

All copy and catalogue data is centralized — **components never hardcode content**:

- Editorial copy → `src/content/`
- Catalogue records → `src/data/`
- Everything is read through `src/services/content-service.ts`
  (`select.*` for synchronous reads, `contentService` for the async provider API).

WordPress is the **admin/editorial layer**; this React site stays the presentation
layer. See [WordPress content layer](#wordpress-content-layer) below and
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

---

## WordPress content layer

There is **no custom admin dashboard in this app**. Editors work in WordPress; the
site reads published content through the REST API via a `ContentProvider`
implementation (`src/services/providers/wordpress/`). Local mock data remains the
development/fallback provider, so the site keeps rendering if WordPress is down.

### Configure

```sh
cp .env.example .env
# then set
VITE_WORDPRESS_API_URL=https://cms.naadbyte.com/wp-json
VITE_CONTENT_PROVIDER=auto     # auto | local | wordpress
```

- `auto` (default): WordPress when `VITE_WORDPRESS_API_URL` is set, otherwise local.
- `local`: bundled catalogue only — useful offline.
- `wordpress`: force the CMS (still wrapped in a local fallback).

Only public, published content is read from the browser. Credentials
(`WORDPRESS_APP_PASSWORD`) are server-only and never prefixed with `VITE_`.

### WordPress setup

Register these custom post types with REST enabled (`show_in_rest: true`) and expose
their fields via ACF (`show_in_rest`) or registered post meta:

| Post type     | Fields (meta / ACF keys)                                                                                                                                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `song`        | `cover`, `audio_url`, `lyrics`, `genre_ids`, `artist_ids`, `album_id`, `release_date`, `duration_seconds`, `language`, `youtube_url`, `spotify_url`, `apple_music_url`, `amazon_music_url`, `featured`, `featured_order` |
| `album`       | `artwork`, `release_date`, `song_ids`, `genre_ids`, `genre`, streaming URLs, `featured`, `featured_order`                                                                                                                |
| `genre`       | `artwork`, `order`, `featured` (title = name, excerpt = description)                                                                                                                                                     |
| `video`       | `youtube_url`, `thumbnail`, `published_date`, `genre_ids`, `featured`, `featured_order`                                                                                                                                  |
| `social_post` | `instagram_url`, `thumbnail`, `caption`, `network`, `published_date`, `featured`                                                                                                                                         |
| `posts`       | core WordPress posts → blog/stories (featured image, excerpt, content)                                                                                                                                                   |

Draft posts are mapped to `status: "draft"` and filtered out of the site.

### How to add content

- **A song** — Songs → Add New. Title, slug, cover image, paste the MP3 URL into
  `audio_url`, fill lyrics/description, pick genres, set `album_id`, release date and
  the streaming URLs. Publish. Tick `featured` (and set `featured_order`) to surface it
  on the homepage.
- **An album/release** — Albums → Add New, set artwork, description, release date and
  the list of `song_ids`. `featured` + `featured_order` control the homepage ordering.
- **A YouTube video** — Videos → Add New, paste the full YouTube URL into
  `youtube_url` (a bare video id also works), add a thumbnail and category.
- **An Instagram/Reel link** — Social Posts → Add New, paste the permalink into
  `instagram_url`, add a thumbnail and optional caption.
- **Featured content** is editor-controlled through the `featured` / `featured_order`
  fields — no hardcoded arrays need editing.

### MP3 / audio URLs

Audio is **never bundled** into the app. Upload the MP3 to the WordPress media
library (or any CDN/object storage) and store the resulting URL in `audio_url`. The
player architecture (`src/services/audio-player.ts` + `src/hooks/useAudioPlayer.ts`)
streams from that URL and already supports play/pause, progress, duration, volume,
queue and next/previous. No player UI is shipped yet — the architecture is in place.

### Switching providers

Change `VITE_CONTENT_PROVIDER` (or unset `VITE_WORDPRESS_API_URL`) and restart the
dev server. Provider resolution lives in `src/services/content-service.ts`.

## Environment variables

- Client-readable values **must** be prefixed with `VITE_` and are exposed in the
  browser bundle — never put secrets there.
- Server-only secrets are read from `process.env` **inside** server code.
- Copy `.env.example` to `.env` locally; `.env` is git-ignored.

| Variable                    | Scope  | Purpose                                      |
| --------------------------- | ------ | -------------------------------------------- |
| `VITE_SITE_URL`             | client | Absolute site URL used for canonical/OG tags |
| `VITE_WORDPRESS_API_URL`    | client | Public WP REST base URL (`.../wp-json`)      |
| `VITE_WORDPRESS_NAMESPACE`  | client | REST namespace, default `wp/v2`              |
| `VITE_WORDPRESS_TIMEOUT_MS` | client | Timeout before falling back to local content |
| `VITE_WORDPRESS_PER_PAGE`   | client | Items per collection request                 |
| `VITE_CONTENT_PROVIDER`     | client | `auto` \| `local` \| `wordpress`             |
| `WORDPRESS_APP_PASSWORD`    | server | Credential for authenticated WP writes       |
| `SONG_REQUEST_WEBHOOK_URL`  | server | Endpoint receiving commission submissions    |

All are optional; with none set the site runs entirely on bundled content.

## Deployment

The build produces a standard client bundle plus a server bundle, so the site can be
deployed as SSR or as a static-ish site behind any Node/edge host.

- **Cloudflare Workers/Pages** (default target): `npm run build`, then
  `npx nitro deploy --prebuilt`, or point Pages at the repo with build command
  `npm run build` and output directory `dist/client`.
- **Vercel / Netlify**: build command `npm run build`, output `dist/client`; both
  detect the generated server bundle in `dist/server` for SSR.
- **Self-hosted Node**: `npm run build` then run the generated server entry in
  `dist/server/index.mjs` behind a reverse proxy.

Set any environment variables in the host's dashboard before the first deploy.

## Portability

The project is plain React + Vite + TypeScript and can be cloned, installed and run
outside the hosted editor with no proprietary services. The Vite setup is provided by
the public npm package `@lovable.dev/vite-tanstack-config`, which bundles the standard
plugins (TanStack Start, React, Tailwind, tsconfig paths, Nitro). If you ever want to
drop it, replace `vite.config.ts` with the equivalent plugin list — nothing else in
`src/` depends on it.
